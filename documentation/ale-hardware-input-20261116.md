# 1.1.4 真实触摸链路

## 反馈与边界

用户iOS17.0真机确认1.1.3悬浮球可显示并能由主App关闭，但不能点击或拖动。因此显示已通过，真实硬件交互未通过；此前内部合成按钮自检不能作为硬件监听、拖动或完整可用的证据。

## 本次修改

- 逐帧处理按下/移动/抬起：原TSEventFetcher共享可变UITouch，CFRunLoopSource多次signal会合并，一次主队列积压可使抬起覆盖尚未派发的按下。真实输入帧现在立即完成派发，未处理标记避免稍后CF回调重复发送。AX数据进入主队列前复制为不可变值。
- 1.1.3原生源已正确初始化，改经UIApplication.sendEvent驱动完整手势环境，覆盖UIPan等识别器；不再仅以UIWindow按钮能点击判定拖动可用。
- 独立只读IOHID Monitor监听，生命周期为HUD进程；失败才使用BKS回调，均在UIKit插件启动完成后注册。只读digitizer，未使用系统事件注入接口，未读取键盘数据；不新增签名权限。
- 路由仅接受起点命中悬浮控件的手势；保持移动/抬起的目标归属。拒绝空目标、非法编号、孤立抬起、重复按下及控件外手势。
- 主App持续显示入口、原始/有效/命中计数，以及球实际点击/拖动计数。只有真实球回调才显示已收到操作；内部自检后仍提示手指操作待确认。诊断不含聊天、Key、按键、触摸坐标或其他App内容。
- 保留已能显示的托管方法、iOS17原生事件源初始化、人设/对象/长期记忆及所有主App功能。数据格式和标识未改。

## 验证

计划真实模拟器运行生产路由：同一轮快速按下/抬起、3次点击、禁用按钮、重复事件、外部/孤立事件、实际UIPan移动UIView；保留原初始化/按钮对照与全部业务检查。它仍不是iOS17真实HID接收或跨App全局托管的证明。

不得在没有真机证据时把硬件输入问题说成完全修好。
