# Windows 微信桌面助手变更记录

此记录从本机独立实现回溯，0.6.3已在本地准备同步，按用户最新要求暂不推送，最终版本统一同步。既有Jev Windows/QQ界面在另一目录，未替换。所有版本的“测试通过”均不能代替真实设备验收。

## 0.7.0 · 2026-10-25

- 保留Tk与六页结构、所有原业务回调，新增appearance.py承担主题、圆角按钮和侧边栏；实际渲染六页检查，调整回复/理由分隔和底部状态栏，模型页增加滚动以确保旧设置仍可访问。采用浅色磨砂视觉，不引入WebView或宣称原生苹果玻璃材质。
- 新增persona.py：全局性格语气、表达习惯与避免表达，单项最多1500字；每段关系可以独立覆盖，未覆盖继承全局。设置在旧DPAPI存储中加密保存，无数据迁移；切换对象保留未保存编辑，保存后新回复生效。全局关闭同时禁用对象人设，历史表达学习独立保留。
- 生成请求将有效人设作为表达偏好数据，与本对象历史、关系阶段/目标和修改示例结合。不得借人设覆盖事实、对方边界或程序安全规则；不主动邀请电话/语音/视频。摘要与关系报告不套用表达型人设。
- 核对window_sender/background_sender/delivery/send_confirmation/runtime/wechat_reader/filehelper_verification与0.6.5逐文件一致，原44处业务command回调保留。没有追加微信实发或真实模型调用，不将旧版实发当本版新实测。源码/冻结EXE测试及布局状态见随包报告。
- GitHub仍按用户要求暂停推送，仅本地记录。

## 0.6.5 · 2026-10-25

- 自动发送开关开启但绑定为0的根因是旧版只自动选择窗口，并不建立关联。现在对所有已连接对象每3秒自动关联，不依赖工作台选中对象；重启后重新匹配当前窗口。
- 使用已核验账号完整通讯录建立名称冲突索引；每对象/每窗口必须唯一，拒绝主窗口、多个微信进程、跨对象占用与身份改变；重名仍需手动核对。用户需先为每位对象打开独立窗口，未实现直接按wxid的Hook。
- 等待窗口的有效自动任务在自动关联成功后继续逐条5秒弹窗；过期任务、开关关闭、未知回执和人工接管保护保持。
- 源码与最终EXE均223项回归通过，含多对象无需切换、未监听联系人重名排除、窗口重建、等待任务恢复；六页UI启动通过。
- 用户明确追加授权一条文件传输助手固定正文，最终EXE实际自动关联、5.64秒默认确认、发送与本机回执成功；前台与剪贴板不变。鼠标采样发生变化，用户确认当时正在使用鼠标，故本轮鼠标不变项不可判定，不伪记通过。生产后台投递代码未改，上一版3轮鼠标不变验收保留为历史证据。无其他联系人实发或真实模型调用。
- 沿用旧数据无迁移；GitHub继续暂停推送。

## 0.6.4 · 2026-10-25

- 真实0.6.3错误栈落在根节点UIA Name比较；进程、父链和根HWND此前已通过。根名称是控件标签，不能强求等于原生窗口标题，上一版条件导致再次误拦截。
- 到达精确绑定根句柄时重新读取原生title/PID/exe，保留前后两次核验，取消不可靠的UIA根标签要求。窗口变化、跨进程或跨根仍拒绝，增加归属子阶段诊断。
- 自行真实测试发现原投递点击仍让Qt微信进入前台，虽然消息有回执也判验收失败。Qt链路改为无点击的定向WM_CHAR输入、全文回读后定向Enter提交；不发激活、聚焦、鼠标消息，不恢复前台。只向文件传输助手做固定内容测试，不向其他联系人试发。
- 新增程序内固定范围自测入口，默认只预检；必须显式允许才发送固定测试文字。实际使用生产确认弹窗、Delivery、WindowSender和数据库回执，最大4次、未知结果不重试，测试数据与正常配置隔离。验收数量见最终报告，冻结EXE通过实际测试前不交付。
- 最终验收：修复后同一文件传输助手连续3轮真实静默投递均有数据库回执，鼠标/剪贴板/前台不变；两轮真实弹窗分别5.43秒与5.30秒默认确认，最后一轮为打包EXE。未调用模型或对其他联系人实发，不扩大声称最小化/锁屏已支持。
- 新增根标签不同但原生身份相同可用、父链遍历期间标题变化仍拒绝的回归；真实微信后台投递仍待验收。推送暂停，仅本地记录。
