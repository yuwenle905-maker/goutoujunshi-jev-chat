狗头微信助手 0.7.0 — 新界面 / 全局与独立人设 / 多对象自动关联

0.7.0 使用说明
- 关闭旧版后双击 GoutouWechat.exe，无需安装 Python。继续使用原有本机加密数据库、Key、对象档案和记忆，不清空或迁移数据。
- 六个页面改为左侧导航；浅色磨砂视觉、圆角按钮、明确的主操作和可调整的回复/理由区域。沿用 Tk 窗口；不是浏览器，也不宣称实现桌面背景实时模糊或苹果原生 Liquid Glass。
- 模型与规则 → 我的人设：设置性格与语气、表达习惯、避免的表达，点击保存全局人设。每项最多1500字，保存后用于新生成的回复。
- 微信与对象 → 选择对象 → 此对象的人设：勾选独立人设，填写后点击保存此对象设置。其他对象不受影响；不勾选则继承全局。全局关闭人设会同时停止使用独立人设，但历史表达学习仍保留。
- 人设结合当前对象历史、已确认摘要、相关旧消息和审核修改示例影响措辞。历史事实、对方明确边界及不主动建议电话/语音/视频始终优先，不编造经历或承诺，不保证对方无法察觉AI辅助。摘要与关系报告不受人设语气改写。
- 原有44处业务操作回调保留；监听读取、自动关联、后台发送、五秒确认、回执、额度与开关的实现文件未改。发送流程沿用此前实测版本，本次不向真实联系人或文件传输助手追加发送消息，不调用真实模型。
- 自动发送仍默认关闭；请连接联系人并核对自动关联状态后选择人工审核或自动发送。设置人设不会补发或重发旧任务。

以下为此前版本的功能和验收记录：

0.6.5 多对象自动关联
- 每位监听联系人先在微信打开独立聊天窗口；程序每3秒匹配全部对象，无需逐人选择“设置发送窗口”，切换工作台不影响其他人。
- 从已核验账号完整通讯录排除名称冲突；同名多窗口、多个微信进程或名称不唯一时不猜测，保留手动关联。窗口标题并非直接微信号证明。
- 新来信已生成、等待窗口的有效自动任务，在关联成功后继续逐条弹窗；过期、关闭开关或未知发送结果不会重发。
- 重启后自动重建匹配；不自动打开微信会话，不保证最小化/锁屏；发送仍需原有草稿/正文回读与本机回执校验。

0.6.4归属校验修正
- 用户0.6.3真实日志精确到根节点Name判断，说明进程、原生句柄与父链均已通过，最后又因UIA根节点标签不同而误拦截。这是本程序多加了不可靠的名称条件。
- 移除UIA根节点名称当联系人身份的假设，改为找到精确的绑定根HWND后再次读取Win32窗口标题/PID/进程路径，三项必须与所选独立窗口一致；前后窗口变化仍拒绝。其他跨进程、跨窗口、主窗口、父链缺失与长度限制均保留。
- 真机测试发现Qt投递点击会激活微信；现不点击输入框或发送按钮，Qt输入只投递WM_CHAR，全文回读一致后向同一绑定窗口投递Enter。发送不恢复、激活或切换窗口，不碰系统鼠标、键盘状态或剪贴板。若当前窗口无法接收字符，不用点击取焦点，会停止并保留已有文字。
- 本机微信4.1.15.13已连续3轮真实静默发送到文件传输助手并取得数据库回执；前台、鼠标、剪贴板均未变化。其中两轮实际5秒默认确认，最后一轮直接运行最终EXE。测试为固定正文，没有调用模型或向其他联系人试发，也未验收最小化/锁屏。
- 诊断新增固定归属失败子阶段，不记录控件名称。仅点检查仍不等于实际投递；本版另附真实验收记录。没有推送GitHub，继续本地记录、最终统一同步。

0.6.3通用输入标签兼容
- 用户本机截图确认输入框实际名称为“输入”，并非联系人名称；0.6.2仍以名称相等校验因此误拦截。现仅对此已观察到的通用标签改用归属校验：绑定HWND当前标题/PID/路径不变，微信进程，每一级UIA父控件PID一致，遇到原生子窗口必须属于绑定根窗口，且父链最终到达标题一致的绑定根窗口。主窗口、跨进程/跨窗口、无父链或归属无法读取均拒绝。
- 找到唯一chat_input_field、账号与对象显式绑定、发送前窗口复核、草稿保护、正文回读及本机记录回执仍保留。窗口归属不是直接读取微信号；最初仍需用户核对微信资料再关联独立窗口。其他未知或真正不同的输入框名称仍拦截。
- 检查界面会注明采用了进程与窗口归属核验。检查不输入不发送；本版本真实微信后台发送尚未验证成功。

0.6.2检查修正
- 用户0.6.1日志证实控件树已出现（87个节点，其中79个mmui节点），找到唯一输入框，但名称校验失败；不是没有找到控件树。原标志已还原、没有发送。
- 修复已确认的解析缺陷：语音提示尾部有空格或换行时，先去外围空白再剥离已知语音提示；精确同名优先，不误剥真实联系人名称里的“语音输入”。依然要求最终名称完全一致，不接受昵称包含或未知后缀。
- 若仍不符，在本机界面显示所选窗口标题与输入框标签（各最多100字符），方便直接对照；日志不保存这两个名称。避免继续只提供无法进一步定位的泛化错误。
- 上述解析缺陷可能解释本机现象，但旧日志未保存原标签，尚不能确定为本次唯一原因；真实微信后台投递仍需验证。

0.6.1检查修正
- 区分仅窗口外壳、输入框缺失、多个输入框与对象名称不匹配。诊断只保存控件数量及固定错误分类，不保存名称、聊天正文或窗口截图。
- 已有输入框但身份不符时立即停止，不再尝试启用标志；启用与失败还原均回读标志核验。等待控件出现延长至最多10次、每次200毫秒，不重试发送。
- 修复部分非Tk滚轮事件造成的日志异常。原有5秒确认流程不变。
- 用户在本机0.6.0检查已真实失败：启用标志后仍未匹配到输入框。本版改善排查与校验，没有把该故障宣称为已修复；真实微信静默发送仍未验证成功。

当前发送方式
- 已替换旧版前台发送器：UI Automation只读取输入值与控件，Qt文字与提交仅通过绑定窗口的定向字符/按键消息投递；原生Edit/Button使用原生子窗口消息。
- 不调用SetForegroundWindow、ShowWindow、SetFocus、全局鼠标键盘或剪贴板，也不使用可能自行聚焦的UIA SetValue/Invoke。失败明确停止，没有前台兜底。
- 发送前检查当前账号/对象绑定、窗口句柄/PID/进程路径/标题及输入框名称；已有草稿停止，输入后必须全文回读一致才提交。成功仍以该对象本机数据库的新自发记录为准，未知结果不重复发送。
- 保留独立窗口绑定以避免误发，不操作会切换对象的微信主窗口。0.6.5自动关联唯一匹配的窗口；其他情况核对后手动关联。自动发送默认关闭。
- 窗口可以在其他应用后面，不要求同时在前台。当前控件树无法提供有效位置、微信升级导致特征不符、权限不足时停止，不把窗口恢复到前台。最小化/隐藏/锁屏的适用性取决于当前微信控件提供方，尚未在本机实发验证，不保证所有这些状态都可用。

首次使用
1. 关闭旧版后运行本EXE，保持微信登录，连接所需联系人。
2. 每人打开一个独立聊天窗口，等待约3秒，检查已绑定数量。唯一名称自动关联；重名或多进程等未匹配的对象才需要工作台“设置发送窗口”手动核对关联。
3. 可点“准备/检查后台控件（不发送）”。它不输入或发送消息；首次会校验当前微信DLL并启用当前进程的一个Qt无障碍运行时标志，不修改安装文件、不重启、不设置系统读屏开关、不注入DLL。已支持并只读校验本机4.1.15.13的特征，其他版本未验证时拒绝修改。启用后仍无控件会尝试还原该标志；还原失败会明确提示重启微信。
4. 检查显示输入可读、文字投递和发送按钮定位可用，只代表前置能力通过，不代表真实消息已发送。先人工审核一条，核对诊断日志里的本机发送回执，再开启自动发送处理之后的新来信。
5. 多人发送按队列串行处理，每人使用各自历史、关系设置和窗口；无需逐条选择工作台或窗口。

审核与自动处理
- 关闭自动发送：生成建议后停在工作台，点击确认发送才打开逐条确认弹窗。
- 开启自动发送：之后新来信生成的合适回复自动打开确认弹窗，显示对象、来信和拟发正文；弹窗显示后5秒内无操作默认确认并后台发送。
- 点击确认可立即发送；点击修改或在弹窗中点击/按键立即停止倒计时，编辑后需再确认。关闭弹窗或取消即取消本条，不默认为同意。
- 多人弹窗依次显示，每条独立计时。新来信、切换连接或关闭开关使旧回复失效时取消。需要人工复核的结果不倒计时；摘要和关系分析不能发送。
- 用户自行接话后暂停该对象自动处理，人工审核仍能发送。若草稿正好等于本次人工确认的全文，可直接核对提交；不会删除或替换其他草稿。
- 上次结果不明或仍在等待回执时停止，核对微信后使用“核对后恢复自动处理”；旧任务不会被重发。
- 工作时间和每日上限继续约束发送；总开关关闭取消任务。新消息到达时，尚未提交的旧回复会被中止。

长期记忆与关系分析
- 同一登录账号可以同时监听多个对象；每人独立阶段、目标、当前状态、背景和边界。
- 开启对象记忆后自动增量保存历史，分批读取，不因超过10000条拒绝读取。
- “长期记忆 → 关系分析与推进 → 分析关系、痛点与推进建议”：使用当前对象跨时段历史抽样、近期文字与已确认摘要，最多约24000字原文，并明确展示本次证据条数，不冒充全量逐条分析。
- 分析包括关系现状、带日期/说话人的原话依据、沟通痛点、注意事项、推进时机和步骤、积极/冷淡/拒绝的分支、一条参考话术和未知。区分事实与推测，不诊断隐秘心理、不提供利用弱点的操控建议；遵守不主动提议电话或视频的偏好。
- 分析使用配置的模型，结果按对象加密保存，不改阶段/目标、不覆盖已核对摘要、不取消待审核回复、不发送。支持取消与100秒超时，失败保留旧结果。清除对象记忆会一并清除此对象分析。
- 审核修改学习仍独立保存每对象最近8个已确认发送的修改示例，辅助表达风格，不是模型权重训练。

诊断与数据
- 诊断日志显示阶段、匿名对象/任务标记、错误分类与栈位置，不记录聊天正文、微信号、窗口标题或API Key。
- 支持刷新、导出诊断包和清空日志。清空同时移除页面与三份滚动日志，不影响聊天、记忆、模型配置或已导出文件。
- 沿用%LOCALAPPDATA%\GoutouWechatAssistant\memory.sqlite3，DPAPI加密，无数据库迁移。模型只连接DeepSeek官方接口；生成时按功能提交当前对象证据和档案。
